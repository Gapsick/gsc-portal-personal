## 프로젝트 개요

GSC Portal은 영진전문대학교 글로벌시스템융합과 학생 및 교원을 위해 개발한
**학과 전용 포털 시스템**입니다.

학과 내에서는 공지·시간표·일정 등의 정보가 분산되어 있어
필요한 정보를 찾는 데 불필요한 시간이 소요되는 문제가 있었습니다.
또한 기존의 범용 도구로는 학년별 관리나 학과 고유의 운영 흐름에 대응하기 어려운 경우가 많았습니다.

이 문제를 해결하기 위해
Vue 3 + Node.js + MySQL 기반의 학과 전용 포털 시스템을 개인이 직접 설계·개발하기 시작하였습니다.

단순 게시판 시스템에 그치지 않고,
Google Calendar와 LINE 등 외부 API 연동을 통해
**알림·공유의 자동화**를 구현한 실용성 높은 시스템을 목표로 하였습니다.

## 주요 기능

### 공지사항 관리

학년별 필터링과 검색 기능으로
필요한 정보를 빠르게 찾을 수 있는 게시판 시스템입니다.

- 학년별 공지 필터링 및 키워드 검색
- 공지 PIN 고정, 파일 첨부, 미리보기 지원
- Google Calendar 일정 자동 등록 옵션
- LINE Messaging API를 통한 자동 알림 전송

**예시:**

![공지사항 리스트](./docs/board.png)

### 일정 관리

Google Calendar API와 연동하여
월간/주간 뷰로 학과 일정을 통합 관리합니다.

- 월간 / 주간 UI로 일정 확인
- 일정 등록 / 수정 / 삭제
- Google Calendar API 연동을 통한 외부 동기화

**예시:**

![일정 화면](./docs/calendar.png)

---

### 시간표 관리

학년별 주간 시간표를 시각적으로 표시하고,
특강·휴강 등의 상태를 직관적으로 파악할 수 있습니다.

- 학년별 주간 시간표 출력
- 교시 병합 표시, 특강/휴강 시각적 구분
- 관리자 전용 시간표 등록 및 수정 기능

**예시:**

![시간표 화면](./docs/timetable.png)

### 사용자 인증 및 권한 관리

대학 도메인으로 제한된 Google OAuth 로그인으로
외부 사용자의 접근을 차단합니다.

- Google OAuth 로그인 (g.yju.ac.kr 도메인 제한)
- 신규 유저는 회원가입 후 관리자 승인 필요
- JWT 기반 자동 로그인 및 토큰 갱신
- 학생 / 교수 / 관리자 권한에 따른 기능 분리

## 시스템 구성

프론트엔드·백엔드·데이터베이스를 명확히 분리한
**3-Tier 아키텍처**로 설계되었습니다.

### Frontend (Vue 3)
- Pinia를 활용한 상태 관리
- SCSS 기반 스타일링
- 라우트 가드를 통한 권한 제어

### Backend (Node.js / Express)
- JWT 발급 및 검증 미들웨어
- Google OAuth 2.0 인증 흐름
- Google Calendar API · LINE API 연동 모듈

### Database (MySQL)
- 사용자·공지·일정·시간표 관계 설계
- 세션 관리 테이블

---

## 🛠 기술 스택

- **Frontend**: Vue 3, Vite, Pinia, SCSS
- **Backend**: Node.js, Express, JWT
- **Database**: MySQL
- **Infra & API**: Google Calendar API, LINE Messaging API

## 기술적 도전과 개선

### Google OAuth 도메인 제한

일반적인 Google 로그인만으로는 누구나 접근할 수 있는 문제가 있었습니다.

→ 메일 도메인을 `g.yju.ac.kr`로 제한하고,
관리자 승인 흐름을 추가함으로써
이중으로 비인가 접근을 차단하는 구조를 구축하였습니다.

---

### JWT 토큰 관리

액세스 토큰 만료 시 매번 재로그인이 필요한 UX 문제가 있었습니다.

→ 리프레시 토큰을 도입하여
액세스 토큰 자동 갱신을 구현함으로써
사용자가 의식하지 않고도 세션을 유지할 수 있도록 하였습니다.

---

### 외부 API 연동의 복잡성

Google Calendar와 LINE 두 가지 외부 API를 동시에 관리해야 하여
에러 핸들링과 인증 정보 관리가 복잡해졌습니다.

→ 각 API의 래퍼 모듈을 분리하고,
서비스 레이어에서 통일적으로 호출할 수 있도록 구성을 정리하였습니다.

## 배운 점

본 프로젝트를 통해
기능 구현뿐만 아니라,
초기 설계가 시스템 전체에 큰 영향을 미친다는 것을 배웠습니다.

인증·권한 관리 등의 기반 설계가
서비스의 확장성에 직결된다는 것을 실감하였고,
설계 단계에서의 의사결정이 얼마나 중요한지를 강하게 의식하게 되었습니다.

또한 여러 외부 API를 개인이 직접 통합·운영하는 경험을 통해,
모듈 분리와 에러 핸들링 등
**유지보수성을 고려한 설계**의 필요성을 실전에서 학습하였습니다.

## 로컬 실행 방법

git clone https://github.com/Gapsick/gsc-portal-personal.git
